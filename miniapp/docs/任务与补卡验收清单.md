# 任务与补卡验收清单

## 自动化检查 已通过

- 直接打卡、同日重复请求不重复加分，取消追加反向流水。
- 首页与任务中心同源，详情与搜索可找到今日任务。
- 跨天、重启、删除任务、阶段推进保留历史积分。
- 旧待确认数据一次性迁移，并保留原数据备份。
- 单次任务在截止日前保留，完成后不在次日重现。
- 连续七天没有正常打卡且有已知任务安排时，开放近七天集中补卡。
- 不允许未来日期、不存在的任务、重复选择、已完成任务重复入账。
- 免费开发额度首次一批，一批多项；重复请求只返回第一次回执。
- 第一次整批写入失败不扣次数、不修改积分，重试可成功。
- 免费用完后不展示虚假购买能力，重启保留已用次数。
- 补卡不填充正常连续打卡，日历和明细可以区分补卡。
- 单次任务补完后立即退出待办，补卡可推进当前目标，不回溯后续阶段。
- 补卡、正常任务完成后对应提醒消除；孩子模式只读任务与补卡提醒。
- 报告汇总补卡数量和积分，模块入口可正常定位。
- 页面批量选择、确认消耗次数、重复点击防护和请求标识已测试。

统一验收命令：在 `miniapp/` 目录运行 `node ../test-data/miniapp-tests/acceptance.js`。逐组运行任务、补卡、首页、成长银行、学习中心、家庭空间和底部导航测试，失败时返回非零退出码。

任务与补卡测试以虚拟日期和内存缓存运行，不修改真实用户记录或额度；各组在独立 Node 进程中执行。此命令不启动微信开发者工具，也不代表真实云同步或真机界面验收通过。

## 微信开发者工具与真机 待验收

- [ ] 编译项目，首页、任务中心、详情、打卡记录均可打开。
- [ ] 在独立测试数据上完成一个任务，首页数量、任务状态和积分同步更新。
- [ ] 关闭并重新打开，记录和积分仍存在；跨天可重新完成重复任务。
- [ ] 打开任务中心的“集中补打卡”，不符合条件时理由明确且不能提交。
- [ ] 在独立的七天未打卡测试数据中，多选任务，确认弹窗明确说明使用一次机会。
- [ ] 确认后只扣一次额度，实际只增加一次所选积分；再次打开显示额度已用。
- [ ] 单次任务补完后不再显示为今日待办；正常连续打卡不被补卡虚增。
- [ ] 打卡明细、积分明细、成长报告显示相同的补卡结果。
- [ ] 智能提醒跳转补卡页，补卡完成后不再出现该提醒。
- [ ] 家长与孩子模式切换后提醒范围正确；全流程无控制台报错。
- [ ] 真机多选、滚动、底部确认区和安全区显示正常。

不建议修改系统时间或在真实账号中伪造历史来验收。使用独立测试账号或测试数据；现有自动化测试已覆盖日期与资格场景。
