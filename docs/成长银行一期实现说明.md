# 成长银行一期实现说明

依据用户提供的成长银行模块开发文档 V1.0，实施本地可运行的核心切片，不声明完成文档全部三期功能或生产合规验收。

## 已实现

- 发现页及我的成长工具提供成长银行入口，游客需登录。
- 五育一级维度与九个二级指标注册配置，德育之智使用 DE.WIS，智育使用 INT 命名空间。
- 文字和最多三张图片的成长记录，先保存再由家长确认；不请求位置、通讯录、生物识别或 AI 服务。
- 家长确认使用基础分、难度、质量、维度权重与每日指标上限；已入账流水保留当时规则版本及系数。
- 业务幂等与追加式冲正，积分与事件在一个本地对象中保存，避免确认中途出现两份数据不一致。
- 新记录积分合入现有余额、明细及兑换功能；旧积分机制不迁移，银行流水仅包含新增记录。
- 数据板复用今日任务、提醒、待审批入口，五育基础图表仅统计已确认银行记录。
- 图表基准暂为每维 100 分，仅表示本版积累进度，不代表发展水平或同龄对比。
- 开启、拒绝、撤销授权，家长导出 JSON，删除记录内容（保留无原文账务凭证及积分）。

## 数据边界

使用 localGrowthBankV1 本地缓存，不包含在现有云同步白名单中。图片由 wx.saveFile 保存于小程序文件空间，不上传。模式切换只提供应用内操作限制，不是独立身份认证。现有账户仍是一家长账号、家长及孩子模式；没有引入跨家庭账号关系。

旧四维记录不强行映射五育，避免虚构分类。新版账务凭证不可原地修改，但现有任务积分仍由旧状态重建，不应将整个系统描述为已经具备生产强一致账务。

## 验证

执行 `node tests/growth-bank.test.js`，覆盖授权闸门、重复记录、重复确认、计分、上限、冲正、防负余额、模式权限、导出、删除、现有积分合并与重建幂等。另执行 JS 语法、WXML 标签与路由文件静态检查。微信开发者工具编译、真机图片权限、文件导出和视觉验收需另行完成。
